# Extracting the coprocessor firmware and palette blobs

This SDK does **not** ship the Sega coprocessor firmware or palette data it boots. That
data is copyrighted by Sega and is not ours to redistribute. You extract it from **your
own ROM dumps** into five generated headers that the build expects in `src/`.

They are git-ignored, so an extraction never lands in a commit by accident.

## What you need

Five headers, each a plain C array generated by [`tools/bin2c.py`](../tools/bin2c.py):

| Header | Array (type) | Halfwords | Source | Needed for |
|---|---|---|---|---|
| `src/cpres1.h` | `cpres_data` (`unsigned short`) | 14862 | Sonic the Fighters | COP (math SHARC) firmware — default profile |
| `src/cpres2.h` | `cpres_data2` (`unsigned short`) | 9351 | Sonic the Fighters | GEO (geometry SHARC) firmware — default profile |
| `src/psled_cpres1.h` | `cpres_data_psled` (`unsigned short`) | 12288 | Power Sled | COP firmware — `-DGS_COP_PSLED` profile only |
| `src/psled_cpres2.h` | `cpres_data2_psled` (`unsigned short`) | 12288 | Power Sled | GEO firmware — `-DGS_COP_PSLED` profile only |
| `src/psled_palette.h` | `psled_poly_palette` (`unsigned short`) | 522 | Power Sled | Poly palette — `-DGS_PSLED_PALETTE` only |

**Only the first two are needed for a default build.** The three `psled_*` headers are
required solely by the Power Sled profiles; leave them absent otherwise.

The `cpres1`/`cpres2` blobs are the ADSP-2106x (SHARC) microcode the game itself DMAs to
its two coprocessors at boot — the same bytes its `copro_down` / `copro_down2` routines
stream to the FIFO. A SHARC opcode is 48 bits = **three halfwords**, so each array's
length is a multiple of 3 and the boot DMA count is `count / 3`; `m2_3d.h` derives both
from `sizeof`, so there is nothing to keep in sync by hand.

Power Sled's poly palette is not in a palette ROM at all — it lives in that game's
**program ROM at `0x128EE`**, with its entry count in the word at `0x128EC`. The entries
already carry the `0x8000` SET bit.

## How to extract

A dedicated extractor is planned for **[stf-tools](https://github.com/biggestsonicfan/stf-tools)**.
Once it exists, use it — it will know the per-game offsets and emit these headers directly.
Until then, `tools/bin2c.py` converts a raw binary you have carved out yourself:

```sh
# bin2c.py <input.bin> <output.h> <array_name> [u32|u16|u8]
python tools/bin2c.py cpres1.bin src/cpres1.h cpres_data u16
python tools/bin2c.py cpres2.bin src/cpres2.h cpres_data2 u16

# Power Sled profiles only:
python tools/bin2c.py psled_cpres1.bin  src/psled_cpres1.h  cpres_data_psled     u16
python tools/bin2c.py psled_cpres2.bin  src/psled_cpres2.h  cpres_data2_psled    u16
python tools/bin2c.py psled_palette.bin src/psled_palette.h psled_poly_palette   u16
```

The array name in the third argument **must** match the table above — `m2_3d.h` and
`m2_color.h` reference those identifiers by name.

## Checking it worked

If a required header is missing, the build stops with a pointer back to this document
rather than a bare "file not found":

```
error: "Missing cpres1.h / cpres2.h. These are Sonic the Fighters coprocessor
        firmware, extracted from your own ROM dump and NOT redistributed with this
        SDK. See docs/firmware-extraction.md."
```

A good extraction boots the COP: `m2_silicon_boot()` returns with the COP reporting
ready, and `m2_obj.h` geometry commits frames. A wrong offset or a length that is not a
multiple of 3 typically shows up as a COP that reports ready but never advances
`COP_WPOS`.

## Please don't commit them

`.gitignore` already covers all five paths. Keep it that way — this repository is
distributed on the understanding that it contains no Sega ROM data.
